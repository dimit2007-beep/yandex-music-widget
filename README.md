# Виджет Яндекс Музыки (рабочий стол Windows)

Компактная плашка поверх всех окон: показывает трек, который играет **на этом
компьютере**, и управляет им. Рядом живёт отдельное приложение «Часы».

## Запуск

Двойной клик по `start.vbs` — запустит виджет и часы без окна консоли.
Повторный запуск ничего не дублирует. Или из терминала:

```
start.bat              # виджет + часы
start.bat -Only widget # только виджет
start.bat -Only clock  # только часы
start.bat -Stop        # остановить оба
```

npm-вариант тоже работает (если `node` в PATH): `npm start`, `npm run clock`.

## Портативная сборка (без Node и npm)

`powershell -File build.ps1` собирает `build\YMMusicWidget` — папку, которая
работает сама по себе и ставит во главу угла только запуск. Весь рантайм
лежит в подпапке `app\`, а в корне — только файлы запуска и автозагрузки:

- `Виджет.vbs` — запустить только виджет
- `Часы.vbs` — запустить только часы
- `Виджет и часы.vbs` — запустить оба (докидывает недостающее, дублей не плодит)
- `Автозапуск виджета.vbs` — включить/выключить автозапуск виджета
- `Автозапуск часов.vbs` — включить/выключить автозапуск часов
- `ЗАПУСК.txt` — шпаргалка

Папку можно держать где угодно и копировать на другой компьютер —
устанавливать ничего не нужно. После переноса папки включите автозапуск
заново (обновятся пути в реестре). `build.ps1 -Zip` дополнительно упакует
всё в zip.

У exe свои иконки: `YMMusicWidget.exe` — жёлтая плашка с нотой,
`YMClock.exe` — жёлтая плашка с циферблатом; в автозапуск часов
прописывается именно `YMClock.exe`, поэтому Windows показывает там
значок часов. Часы рисуют `clock.ico` по образцу `icon.ico`
(перегенерировать: `powershell -File make-clock-ico.ps1`).

Node.js и npm нужны только для разработки и пересборки (`npm run build`).

`templates\` — это исходники-шаблоны, а не рабочие файлы: сам по себе
такой vbs не работает (рядом нет папки `app`). Запускать нужно из
собранной папки — шаблон при попытке запуска из исходников сам
подскажет об этом сообщением.

## Что умеет

- 🔒 Фрилесс-окно поверх всех окон, перетаскивается мышью (за пустые места)
- 🎵 Обложка, название трека, бегущий прогресс-бар и время (гладкий таймер:
  часы тикают сами между сэмплами состояния)
- ♡ Лайк / снять лайк
- ⏮ ▶ ⏸ ⏭ Пауза, игра, следующий, предыдущий
- 🕒 Отдельное приложение «Часы» (ЧЧ:ММ 24ч): свой процесс/трей, своя
  прозрачность и фиксация; ПКМ по часам — своё меню
- 🗘 Трей и ПКМ по плашке: показать/скрыть, кнопки вкл/выкл, прозрачность 0–100%,
  «Зафиксировать положение», «Перезапустить Яндекс Музыку», вход (по желанию),
  сброс токена, закрыть
- 🖥 На рабочем столе виджет интерактивен, поверх приложений — клик-сквозь
  (кроме кнопок плеера, они всегда живые)
- ↔ Размер и позиция обеих плашек запоминаются автоматически

## Вход не обязателен

Показ и управление работают без всякой авторизации: состояние читается прямо
из приложения Яндекс Музыки (или из системной медийной сессии Windows), а
команды жмут настоящие кнопки в приложении.

Вход через Яндекс (ПКМ → «Вход через Яндекс…») добавляет только мелочи:
- чистые название/артисты/альбом вместо сырых из DOM приложения;
- обложку и лайк у SMTC-резерва (когда приложение ЯМ закрыто).

Токен хранится только на твоём компьютере (`%APPDATA%\yandex-music-widget`);
выйти — «Сбросить токен (выйти)» там же в меню.

## Как это работает

Три источника, от основного к резервному:

1. **CDP** — подключение к отладочному порту (9222) самого приложения
   Яндекс Музыки. Читает DOM плеера (название, обложку, слайдер прогресса,
   статус лайка), команды посылает кликами по настоящим кнопкам.
   Если ЯМ запущен без порта — виджет сам перезапустит его с портом
   (не чаще раза в 10 минут).
2. **SMTC** — системная медийная сессия Windows (та самая, что рисует
   плашку громкости). Резерв, когда ЯМ закрыт: есть название/артисты/время,
   но нет обложки и лайка.
3. **REST API** (`api.music.yandex.ru`, только при входе) — обогащение:
   каноничные имена, артисты через альбом, обложка и лайк для SMTC-резерва.

Прогресс-бар — монотонные часы в рендерере: тикают сами между сэмплами
(сэмплы приходят раз в ~2 с и с точностью до целой секунды), якорь
переприменяется только при реальном сдвиге — перемотке, смене трека,
буферизации. Дисплей движется без рывков и откатов.

## Автозапуск (по желанию)

В портативной сборке — два отдельных переключателя: `Автозапуск
виджета.vbs` и `Автозапуск часов.vbs` (один запуск включает,
ещё один — выключает; записи в `HKCU\...\Run`, у каждого своя).
Запись часов указывает на `app\YMClock.exe` — лаунчер со своей иконкой,
который запускает `YMMusicWidget.exe --clock` и сразу завершается.

Для dev-запуска из папки репозитория — вручную через реестр
(путь подставь свой):

```powershell
New-ItemProperty -Path "HKCU:\Software\Microsoft\Windows\CurrentVersion\Run" `
  -Name "YMMusicWidget" `
  -Value "D:\programms\yandex-music-widget\node_modules\electron\dist\electron.exe D:\programms\yandex-music-widget" `
  -PropertyType String -Force
```

## Файлы

- `main.js` — виджет: окно, трей, меню, OAuth, службы, IPC
- `clock-main.js` — отдельное приложение часов (запуск: `electron . --clock`)
- `cdp.js` — читалка состояния из приложения ЯМ по DevTools-протоколу + клики
- `smtc.js` — резервный источник: системная медийная сессия Windows (PowerShell)
- `ym-api.js` — REST API Яндекс Музыки (обогащение и лайки; нужен токен)
- `foreground.js` — «поверх всех» / «только рабочий стол», z-порядок, клик-сквозь
- `menu-popup.js`, `menu-popup.html/css/renderer.js`, `preload-menu.js` — popup-меню по ПКМ
- `renderer.js`, `index.html`, `styles.css`, `preload.js` — плашка
- `clock.html`, `clock.css`, `clock-renderer.js`, `preload-clock.js` — часы
- `start.bat`, `start.ps1`, `start.vbs` — запуск и остановка
- `build.ps1` — сборка портативной папки `build\YMMusicWidget` (без Node/npm)
- `templates\` — шаблоны стартеров и инструкция для портативной сборки
- `icon.ico` — иконка виджета; `clock.ico` — иконка часов
- `make-clock-ico.ps1` — генератор `clock.ico` (стиль берёт из `icon.ico`)
- `clock-launcher.cs` — исходник `YMClock.exe` (компилируется в build.ps1)
- `probe-cdp.js` — ручная проверка CDP (для отладки)
- `vendor/ws` — WebSocket-клиент (нужен для CDP; вендорная копия — без npm install)
